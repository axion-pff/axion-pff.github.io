Axion

Autodifferentiable, XLA-compiled, Implicit, On-device Numerics

A differentiable, GPU-native finite element framework written in JAX, demonstrated on phase-field fracture.

One compiled program

Same problem, same discretization

The element kernels, the Newton and Krylov iterations, the bound-constrained updates, the staggered coupling of fields and the loop over load increments are a single program, just-in-time compiled and executed on the GPU. Below: two-dimensional single-edge-notched tension, a serial FEniCSx implementation on one CPU vs. Axion on one GPU.

Finite element analysis is increasingly used not only for forward simulation but also within inverse analysis, uncertainty quantification, optimal design, digital twins and scientific machine learning. These workflows evaluate the same model thousands of times and need derivatives of the solution with respect to material parameters, geometry, boundary conditions or constitutive laws. Axion is designed so that finite element analysis and gradient-based learning use the same programming model, compiler and hardware.

How it works

The solution process as a single compiled program

The user supplies the weak form of each field; Axion generates everything else.

Axion is written in JAX, which provides automatic differentiation, vectorized mapping (vmap) and just-in-time compilation through the XLA compiler. A coupled problem is a set of fields. For each field the user writes an element-level weak-form kernel; the residual evaluation, the tangent construction, the linear solution, the treatment of constraints and the solution control are generated from it.

∇

One element definition per field

The element residual and its consistent tangent come from the same kernel: the tangent columns are forward-mode Jacobian-vector products. No hand-derived tangents.

▦

Fixed array shapes

Operators are applied element by element without assembling a sparse matrix; refined meshes live in fixed-capacity buffers and bounds are enforced by projection.

⚡

Compiled control flow

Load increments are a compiled scan; the staggered, Newton and Krylov iterations are compiled while-loops. The host is involved only before and after the simulation.

🧮

Differentiable solution map

Forward-mode derivatives of the discrete solution with respect to model parameters are obtained by differentiating the same program, with each nonlinear solve differentiated implicitly at its converged state. They agree with central differences to below 10⁻⁹.

🌲

Adaptive refinement

Quadtree / octree refinement with 2:1 balance and hanging-node constraints, executed on the device; kernels recompile only when a buffer capacity is exceeded.

🖥️

Multi-GPU execution

A cell-based domain decomposition runs the same program on several GPUs, with halo exchange and global reductions inside the Krylov solver.
